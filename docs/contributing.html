Thank you so much for considering contribution to dsolv!

First, please read the dsolv Code of Conduct. This project will not take any contribution coming from those who do not abide by the code of conduct. This means that if a person is currently under disciplinary action via avenues set forth in that document, we will ignore your PR and/or any issues you may log.

A contribution can be large or small, code or non-code. To make a contribution, first log a GitHub issue. Talk about what you want, and ask for other's opinions. The project tracks its work with Beads issues in the repository.

When you go to make the PR, please use the following checklist to test whether or not it is likely to be accepted:

  1. Is it based on the main branch?
  2. main
  3. Do you have tests in your PR, and do they pass?
  4. tests/
  5. (using Parachute)
  6. test/resources/scripts
  7. (and preferably one or more unit tests)
  8. Is your PR backwards compatible?
  9. Did you add documentation around the feature in your PR?
  10. Command Reference
  11. (see the docs-writing instructions in the repository's .agents/skills/ directory)
  12. Did you add an entry to the Changelog?
  13. CHANGELOG.md

There are some exceptions to the above rules. For example, if your patch is less than two lines' difference from the previous version, your PR may be a "typo" PR, which may qualify to get around some of the above rules. Just ask the team on your GitHub issue.
