This guide describes the dsolv CLI: what subcommands and options there are, and what they are for. It also describes how to specify options.

How Options Are Gathered

dsolv is a CLIFF-powered program. Options can be given via configuration files, environment variables, and the command line, in that order, with later values overriding earlier ones.

Configuration files are consulted from a system-wide location (/etc/dsolv/config.nrdl on Linux), a home-directory location (~/.config/dsolv/config.nrdl on Linux), and a file named .dsolv.nrdl in the current directory (or any of its parents). Files can also be specified explicitly with the -c/--config-file(NRDL) and -j/--json-config(JSON) options. When multiple files are given, later files override earlier ones.

Every option has a corresponding environment variable, named DSOLV_<KIND>_<OPTION>:

  • DSOLV_FLAG_<OPTION>=1 enables a flag
  • DSOLV_ITEM_<OPTION>=<VALUE> sets a string value
  • DSOLV_LIST_<OPTION>=<V1>,<V2>,... sets a list option
  • DSOLV_TABLE_<OPTION>=<K1>,<V1>=<K2>,<V2>=... sets a key/value table option
  • DSOLV_NRDL_<OPTION>=<NRDL_STRING> sets a value using a NRDL string
  • DSOLV_FILE_<OPTION>=<FILE_PATH> sets a value from a NRDL document in a file, as if by the --file-* flag
  • DSOLV_RAW_<OPTION>=<FILE_PATH> sets a value from the raw bytes of a file, as if by the --raw-* flag

For compatibility with degasolv, the legacy DEGASOLV_* environment variables are aliased to their DSOLV_* equivalents; for example, DEGASOLV_REQUIREMENTS is an alias for DSOLV_LIST_REQUIREMENTS and DEGASOLV_CONFIG_FILES for DSOLV_LIST_CONFIG_FILES. The full alias table is printed on the help page.

On the command line, each option can be set with a --set-<option> <value>(string), --add-<option> <value>(list), --join-<option> <key>=<value>(table), --nrdl-<option> <nrdl>(NRDL string), or --enable-<option>/--disable-<option>(flag) form. The legacy degasolv spellings (--requirement, --repository, -r, -R, and so on) are provided as command line aliases, and are what the rest of this guide uses.

A Note on Specifying Files

Whenever an option takes a file, the user can specify one of four things:

  1. An http:// or https:// URL. URL-encoded authentication can be specified before the @ character:
    • https://username:password@example.com/... for HTTP basic authentication
    • https://token@example.com/... for an OAuth2 bearer token
    • https://X-Auth-Token=value@example.com/... for a custom HTTP header
  2. A file:// URL.
  3. A plain filesystem reference.
  4. The character -, signifying standard input.

This is true for options of dsolv and options of any of its subcommands.

Global Options

These options are accepted by dsolv itself and are available to every subcommand:

-c, --config-file <file>
Add an NRDL configuration file. May be specified multiple times; later files override earlier ones. Environment: DSOLV_LIST_CONFIG_FILES / DEGASOLV_CONFIG_FILES.
-j, --json-config <file>
Add a JSON configuration file. May be specified multiple times; later files override earlier ones. Environment: DSOLV_LIST_JSON_CONFIG_FILES / DEGASOLV_JSON_CONFIG_FILES.
-k, --option-pack <pack>
Apply an option pack, a bundle of default option values. Available packs are v1, multi-version-mode, and firstfound-version-mode (see Strategies and Package Systems below). May be specified multiple times. Environment: DSOLV_LIST_OPTION_PACKS / DEGASOLV_OPTION_PACKS.
-h, --help, help
Print the help page.
--meta <key>=<value>
Set a metadata key/value pair. May be specified multiple times. Environment: DSOLV_TABLE_META.

Strategies and Package Systems

Several options control how resolution behaves. They are shared between subcommands that resolve dependencies.

-t, --package-system <system>
The package system to use for slurping repositories. One of degasolv(the default; .dscard/.dsrepo files), apt(Debian Packages.gz indexes), git(a stub), or subproc (an external executable). Environment: DSOLV_ITEM_PACKAGE_SYSTEM / DEGASOLV_PACKAGE_SYSTEM.
-e, --search-strat <strat>
Search strategy: breadth-first(default) or depth-first.
-f, --conflict-strat <strat>
Conflict strategy: exclusive(default), inclusive, or prioritized.
-L, --list-strat <strat>
List strategy: lazy(default), eager, or as-set.
-s, --resolve-strat <strat>
Resolve strategy: thorough(default) or fast.
-S, --index-strat <strat>
Index aggregation strategy: priority(default) or global.
-O, --index-sort-order <order>
Sort order for repository index entries: descending(default) or ascending.
-V, --version-comparison <scheme>
The version comparison scheme: debian, maven, naive, python, rpm, rubygem, or semver(the default). Provided by the svers library.
--enable-alternatives / --disable-alternatives
Whether to consider alternative versions of a package (default: enabled). Environment: DSOLV_FLAG_ALTERNATIVES / DEGASOLV_ALTERNATIVES.
--enable-error-format / --disable-error-format
Whether errors are printed as NRDL/JSON documents (default: disabled). Environment: DSOLV_FLAG_ERROR_FORMAT / DEGASOLV_ERROR_FORMAT.
-o, --output-format <format>
Output format: plain(default), json, or nrdl.

Using Site-Wide Configuration Files

The way configuration files are merged (see How Options Are Gathered above), together with the fact that configuration files may be given as http:// or https:// URLs (see A Note on Specifying Files above), makes it possible to configure every dsolv installation in an organization from a single, centrally served configuration file.

Several options fundamentally change how dsolv behaves: --conflict-strat, --index-strat, --resolve-strat, and --search-strat(see Strategies and Package Systems above). It is recommended that these options be specified site-wide, if they are specified at all. Putting them in a site configuration file and serving that file internally over HTTP(S) lets each build point at the site file together with its own build-specific configuration, as in this example:

dsolv \
    --config-file "https://nas.example.com/dsolv/site.nrdl" \
    --config-file "./.dsolv.nrdl" \
    generate-card

Remember that configuration files can also be specified with environment variables. The example above looks like this when environment variables are used, setting the --config-file option for every invocation:

export DSOLV_LIST_CONFIG_FILES="https://nas.example.com/dsolv/site.nrdl,./.dsolv.nrdl"
dsolv generate-card

Here is the same example using JSON configuration files:

export DSOLV_LIST_JSON_CONFIG_FILES="https://nas.example.com/dsolv/site.json,./.dsolv.json"
dsolv generate-card

For compatibility with degasolv, the legacy DEGASOLV_CONFIG_FILES and DEGASOLV_JSON_CONFIG_FILES environment variables are aliases for DSOLV_LIST_CONFIG_FILES and DSOLV_LIST_JSON_CONFIG_FILES respectively.

As with any configuration that may contain passwords or API tokens (for example, in the URLs of configuration files or repository indexes), decide how sensitive information should reach dsolv. Options include environment variables, standard input (- as the filename), configuration files with appropriate filesystem permissions, or the command line itself; dsolv leaves the choice of what is sufficiently secure to you.

Subcommand: resolve-locations

Resolve dependencies and print package locations. This is the heart of dsolv: it takes requirements, a repository, and strategy options, and returns the locations of the packages that satisfy the requirements.

Arguments used by resolve-locations:

-r, --requirement <req>
Add a requirement, such as a>2.0,<3.0 or !b. May be specified multiple times. Required. Environment: DSOLV_LIST_REQUIREMENTS / DEGASOLV_REQUIREMENTS.
-R, --repository <url>
Add a repository to consult. May be specified multiple times. Required (unless the package system provides its own query constructor). Environment: DSOLV_LIST_REPOSITORIES / DEGASOLV_REPOSITORIES.
-p, --present-package <id==version>
Declare a package as already present in the build, in the form id==version. May be specified multiple times. Environment: DSOLV_LIST_PRESENT_PACKAGES / DEGASOLV_PRESENT_PACKAGES.
-o, --output-format <format>
Output format for the resolution result: plain(default), json, or nrdl.
-t, --package-system <system>
The package system to use (see Strategies and Package Systems).
-e, --search-strat <strat>
Search strategy: breadth-first or depth-first.
-f, --conflict-strat <strat>
Conflict strategy: exclusive, inclusive, or prioritized.
-L, --list-strat <strat>
List strategy: lazy, eager, or as-set.
-s, --resolve-strat <strat>
Resolve strategy: thorough or fast.
-S, --index-strat <strat>
Index aggregation strategy: priority or global.
-V, --version-comparison <scheme>
Version comparison scheme (see Strategies and Package Systems).
--enable-alternatives / --disable-alternatives
Whether to consider alternative versions of a package.
--enable-error-format / --disable-error-format
Whether errors are printed as documents.
-m, --meta <key>=<value>
Set metadata on the result.
-k, --option-pack <pack>
Apply an option pack.
-c, --config-file <file> and -j, --json-config <file>
Specify configuration files (see Global Options).

Subcommand: generate-repo-index

Generate a .dsrepo repository index from the .dscard files found under a search directory.

Arguments used by generate-repo-index:

-d, --search-directory <dir>
The directory to search for .dscard files. Default: .. Environment: DSOLV_ITEM_SEARCH_DIRECTORY / DEGASOLV_SEARCH_DIRECTORY.
-I, --index-file <file>
The index file to write. Default: index.dsrepo. Environment: DSOLV_ITEM_INDEX_FILE / DEGASOLV_INDEX_FILE.
-a, --add-to <file>
If given, an existing index to merge the new entries into, rather than starting from an empty index.
-O, --index-sort-order <order>
Sort order for the index entries: descending(default) or ascending.
-V, --version-comparison <scheme>
Version comparison scheme used for sorting. Default: semver.

Subcommand: generate-card

Generate a .dscard file representing a package in a dsolv repository.

Arguments used by generate-card:

-i, --id <id>
The package id. Required. Environment: DSOLV_ITEM_ID / DEGASOLV_ID.
-v, --version <version>
The package version. Required. Environment: DSOLV_ITEM_VERSION / DEGASOLV_VERSION.
-l, --location <url>
Where the package artifact can be downloaded. Required. Environment: DSOLV_ITEM_LOCATION / DEGASOLV_LOCATION.
-r, --requirement <req>
Add a requirement of this package. May be specified multiple times.
-m, --meta <key>=<value>
Set additional metadata fields on the card. Keys that conflict with the card's built-in fields (id, version, location, requirements) are ignored.
-C, --card-file <file>
Where to write the card. Default: ./out.dscard. Environment: DSOLV_ITEM_CARD_FILE / DEGASOLV_CARD_FILE.

Subcommand: query-repo

Query a repository for the packages matching a query, without resolving.

Arguments used by query-repo:

-R, --repository <url>
Add a repository to query. May be specified multiple times. Required.
-q, --query <query>
The query, a requirement such as e or e>=1.8.0. Required. Environment: DSOLV_ITEM_QUERY / DEGASOLV_QUERY.
-S, --index-strat <strat>
Index aggregation strategy: priority or global.
-o, --output-format <format>
Output format: plain, json, or nrdl.
-t, --package-system <system>
The package system to use.
-V, --version-comparison <scheme>
Version comparison scheme.
--enable-error-format / --disable-error-format
Whether an empty result set is reported as an error document.

Subcommand: display-config

Display the effective configuration, after merging configuration files, environment variables, and the command line.

Arguments used by display-config:

-o, --output-format <format>
Output format: plain, json, or nrdl.
-c, --config-file <file> and -j, --json-config <file>
Specify configuration files whose effective contents should be shown.

The Default Action

Running dsolv with no subcommand prints a short usage message and the list of available subcommands. To learn more about a specific subcommand, run dsolv <subcommand> help or pass --enable-help.

Notes on Versions

  • On a best-effort basis, features have had the version that they first appeared associated with them in this guide.
  • As of version 1.3.0 of degasolv (whose CLI dsolv mirrors), all options which take a file may be given - as the filename to specify standard input. dsolv inherits this behavior.
